# v1.1.0 — 换一种方式找门锁，扫不到时能说清原因

> ## 升级方式
>
> 签名没变（v1.0.2 起就是同一张固定证书）。**1.0.2 / 1.0.3 直接覆盖安装，门禁数据保留。**
>
> 仍在 **1.0.1 或更早**：配置 → **导出**（文本/二维码）→ 卸载 → 安装本版 → **导入**。
> 卸载会清空应用数据：门禁用 Android Keystore 加密，密钥随卸载销毁，系统备份也救不回来。

## 这一版在修什么

issue #5：同一份门禁数据在 iOS 复刻版能开，安卓版却「扫描不到门锁」。

原因出在**找门锁的方式**：安卓版此前把「先扫描、再按广播里的名字认门锁」当成唯一入口，第一次开锁必须先扫到。广播侧或扫描环境任一环节不顺，就彻底无解。而安卓本来有一条 iOS 没有的路——手里有真实 MAC 就能直接连，不看广播，也不受系统定位开关影响。

## 找门锁的顺序变了

现在是「上次连上的地址 → 门禁 MAC 直连 → 扫描」，前两步成功就完全不用扫描：

- **直连**：不依赖广播，也不需要系统定位。抓包里拿到真实 MAC 的话，第一次开锁就能用上。
- **推导出来的 MAC 会被认出来**：iOS 复刻版和自动获取在拿不到真实 MAC 时，会按蓝牙名造一个 `00:0x:` 开头的地址。它的尾号能用来握手，但不是真的蓝牙地址，现在不会拿它去直连白等一轮，而是直接走扫描。
- **直连失败会回退扫描**：同一轮里扫描能连上，就记住这台门锁「不支持直连」，10 分钟内不再先尝试直连。只是不在门前（扫描也没找到）不会被记下。
- **连接失败不再清掉缓存的地址**。缓存里存的可能是扫描学到的真实地址。

门禁 MAC 的直连预算 6 秒，上次连上的地址沿用原来的 8 秒；快速模式不直连；静默开锁仍只认缓存地址。

## 扫不到时，能看清是哪一环

以前不管哪种情况，都只有一句「扫描超时，未找到门锁」。现在分开说：

| 情况 | 提示 |
|---|---|
| 缺蓝牙权限 / 定位没开 | 直接给出「**去设置**」按钮（Android 11 起权限被拒两次后系统不再弹窗，以前只能自己去翻设置） |
| 一台设备都没扫到 | 「附近没有发现任何蓝牙设备，请靠近门锁…」 |
| 扫到了但不匹配 | 「发现 N 台蓝牙设备，但没有一台与这条门禁匹配」 |
| 扫描被系统拒绝 | 错误码翻译成人话（例如「扫描启动得太频繁，请等半分钟再试」），且不再自动重试 |

**「扫描与诊断」面板**现在显示：系统定位开关、蓝牙权限、每台设备对当前门禁的**匹配依据**（✓ MAC / ✓ 名字 / ✓ 广播数据），并且可以：

- **手动绑定**：点一下把某台设备记为这条门禁的直连地址，下次直接连它。门锁广播里没有名字也能用。
- **复制日志 / 复制诊断信息**：整份拷走贴到 issue 里，不用截图。

## 连上门锁之后也对齐了两处

- 订阅时按特征属性选择写「通知」还是「指示」。只支持指示的特征以前会被拒绝，回执收不到，表现为「等待门锁回执超时」，而门其实可能已经开了。
- 服务发现优先认已知的厂商服务 UUID（`14839ac4-…`、`0734594a-…`），其余顺序不变。门锁带多个可读写服务时不会选错。

## 其他

- 门禁数据解码逐条容错：一条坏了只丢那一条，其余照常用，并把原始密文另存一份，不会被后续写入覆盖；首页会提示「有 N 条门禁读不出来」。
- 写操作加锁，避免主线程和开锁流程互相覆盖（比如刚记下的直连地址被一次「切换门禁」冲掉）。
- 「取消」按钮修好了：流程正忙时再点一次开锁，以前会让取消按钮失灵。
- 后台开锁（小组件）在 Android 14+ 缺权限时不再抛异常，改为提示并打开 App。
- Android 13 起冷启动会申请通知权限：小组件开锁的进度和结果靠通知回报。

## 尚未验证

**真实门锁仍未开过一次锁。** 这一版的所有改动都过了单元测试，界面部分在 Android 15 的模拟器上走通了安装、授权、新增门禁、失败提示、日志与诊断、复制回读；但模拟器没有蓝牙服务，**直连、扫描、握手这些真实蓝牙行为一条都没有在真机上验证过**。

直连耗时、是否存在「不支持直连」的门锁、门锁的通知特征是通知还是指示，都还需要真机确认。如果你试了，欢迎在 issue 里反馈日志（首页 → 运行日志 → 复制）。
